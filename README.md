# Сайт архимандрита Мелхиседека

Статика без сборщика: HTML + CSS + ванильный JS, ноль зависимостей. Страницы
разделов и элементов генерируются один раз скриптом на Node и лежат в репозитории
готовыми — на отдачу это обычные файлы. Открывается двойным кликом по
`index.html`, но лучше — через локальный сервер (иначе некоторые браузеры
блокируют локальные шрифты):

```
python -m http.server 8000
# затем http://localhost:8000
```

## Единая раскладка разделов

У каждого пункта меню своя страница. Страница раздела устроена одинаково:
заголовок и вертикальный список элементов, **15 на страницу**, дальше пагинация.
В строке списка только подпись и название — описаний нет.

Список отдаётся разметкой целиком, страницы нарезает `main.js` по атрибуту
`data-paginate="15"` на `.entry-list`. Без JS раздел остаётся рабочим: видны все
элементы, просто без переключателя. Номер страницы пишется в адрес (`?page=3`).

Элемент, у которого страницы ещё нет, размечается строкой `.entry-row.is-locked`
— она стоит в списке, но не открывается.

Страница элемента: общая шапка → стрелка назад с названием раздела → заголовок
во всю ширину → лид во всю ширину → содержимое (текст, книга или видео) →
ссылки на соседние элементы.

## Как менять содержимое

| Задача | Куда |
|---|---|
| Добавить встречу, книгу, видеозапись; поправить биографию | `tools/content.js`, затем `node tools/build-pages.js` |
| Добавить расшифровки | пересобрать исходник из `.docx` (ниже), затем `node tools/build-pages.js` |
| Цвет, размер шрифта, отступы | `assets/css/tokens.css` |
| Ширина колонки в длинном чтении (сейчас 75% контейнера) | `--measure-read` в `tokens.css` |
| Сколько элементов на странице раздела | `data-paginate` в `tools/build-pages.js` |
| Отразить портрет в hero обратно | `--portrait-flip: 1` в `tokens.css` |
| Мероприятие на главной | панель `.event-detail` + строка `.event-item` в `index.html` |
| Пункты полосы-меню, порядок, название раздела | `SECTIONS` в `tools/content.js` (`menu: true` — пункт в полосе) |
| Наполнить пустой раздел | снять `empty: true` в `SECTIONS` и собрать раздел как остальные |

Навигация устроена так: в шапке только имя и кнопка «Автобиография», разделы
живут в полосе-меню (`.sitebar`) — на главной под первым экраном, на остальных
страницах сразу под шапкой. Полоса видна на любой ширине, всплывающего меню и
бургера нет. В подвале — все разделы, включая те, которых нет в полосе
(«Мероприятия», «Расшифровки», «Автобиография»).

Главная собирается руками: она одна и живёт по своим правилам. Сборщик её
не трогает, но полосу-меню и подвал на ней нужно держать в согласии с
`SECTIONS` из `tools/content.js`.

Мероприятия на главной связаны как вкладки: у кнопки `aria-controls="event-panel-N"`,
у панели `id="event-panel-N"` и `aria-labelledby="event-tab-N"`. Первая пара —
без `hidden`, у неё `aria-selected="true"`. Остальные панели с `hidden`.

## Расшифровки

Каждый эфир — самостоятельная страница `texts/beseda-NN.html`. Содержания
внутри нет: список эфиров живёт на странице раздела, соседние эфиры даны
ссылками под текстом.

Источник — одна большая страница со всеми эфирами подряд:
`assets/docs/texts/besedy-s-batyushkoy.source.html`. Она собирается из `.docx`:

```
powershell -ExecutionPolicy Bypass -File tools/docx-to-page.ps1 `
  -Source "assets/docs/texts/ИМЯ.docx" `
  -Out "assets/docs/texts/besedy-s-batyushkoy.source.html" `
  -Title "Заголовок материала" `
  -Lead "Одно предложение о материале"
```

Что скрипт берёт из документа: стиль Title — заголовок, List Paragraph —
оглавление, остальное — тело. Абзац, совпавший с очередной записью оглавления,
становится заголовком части; жирный абзац — репликой ведущего (`.is-host`),
курсив сохраняется. Даты вида «8 февраля 2013» и «24.08.11» распознаются.
В конце скрипт печатает, сколько частей сопоставлено с оглавлением: если число
меньше, чем записей, заголовки в теле документа расходятся с оглавлением.

Дальше `node tools/build-pages.js` режет источник по `.part` на отдельные
страницы и заново собирает список раздела.

## Книги

Книга открывается внутри обычной страницы элемента: развороты рисует pdf.js
в `<canvas>` прямо на фоне сайта, листаются стрелками, свайпом и клавишами
`← →`. Под книгой — счётчик разворотов и ссылки на файлы. Если модули или
pdf.js не поднялись, показывается встроенный просмотрщик браузера.

Новая книга — запись в массиве `BOOKS` (`tools/content.js`) с путём к PDF;
без `pdf` и `slug`, но с `locked: true` она встанет в список неоткрываемой
строкой.

Ссылка на EPUB размечена, но пока пустая: `href=""` и класс `is-disabled`
(кнопка не нажимается). Когда файл появится — подставить адрес и убрать класс,
в разметке рядом стоит комментарий `TODO`.

## Проверено

- 85 сгенерированных страниц, ошибок в консоли нет (проверено на разделах,
  расшифровке, книге, встрече и видеозаписи).
- Пагинация: 63 расшифровки → 5 страниц по 15, адрес обновляется (`?page=2`),
  без JS список виден целиком.
- Раскладка 390 / 1280 px, горизонтальной прокрутки нет.
- Книга: 265 разворотов, счётчик и листание работают.
- `prefers-reduced-motion` отключает все анимации.

Проверено раньше и не менялось: W3C-валидатор на главной, axe-core (WCAG 2.1
A/AA), контраст текста (минимум 5.2:1, основной текст 14.9:1), отсутствие
красных и бордовых оттенков.

## Что не сделано намеренно

- Страницы встреч и видеозаписей описывают материал коротко: реальных
  расширенных описаний под них пока нет.
- Файл EPUB: ссылка размечена, но пустая.
- Обложки видео и мероприятий: реальных кадров нет, стоят тёплые плашки.
- Пагинация клиентская: поисковику видна только первая страница раздела.
